## 第二阶段：吃透"数据驱动"（核心，2-3 天）

Vue 的灵魂一句话：**你只管改数据，页面自动变**。
对比传统写法：原生 JS 要 `document.getElementById(...).innerHTML = xxx` 手动改页面，
Vue 里你改 `todos.value = 新数组`，列表自己刷新。全程读 `src/views/TodoList.vue`：

- **`ref()`**：把普通变量变成"响应式"——Vue 在监视它，一变就刷新页面
  （JS 里要 `.value` 访问，模板里不用）
- **`v-model`**：输入框和变量双向绑定，打字 = 改数据
- **`@click` / `@keyup.enter`**：事件绑定，等号右边是函数名
- **`v-for` + `:key`**：循环渲染列表
- **`v-if` / `v-else`**：条件渲染（看 Chat.vue 的用户/AI 气泡切换）
- **`computed`**：由别的东西算出来的值，依赖变了自动重算（看 `filteredTodos`）
- **`onMounted`**：组件出现在页面后执行，发首屏请求的地方

### 跟着一个点击走完整条数据流（必读！）

以「勾选完成一条待办」为例，这 条链路串起了 80% 的前端概念：

```
你点击勾选框
  → TodoItem.vue 里 @change 触发 emit('toggle', todo)     [子组件报告事件]
  → 父组件 TodoList 的 @toggle="handleToggle" 接住         [父组件处理]
  → handleToggle 调 updateTodo(id, {...})                  [api/index.js]
  → axios 发 PUT /api/todos/3                              [相对路径]
  → vite.config.js 的 proxy 转发给 127.0.0.1:8010          [开发期跨端口]
  → FastAPI 写 SQLite，返回新数据
  → await loadTodos() 重新拉列表，todos.value = 新数组       [数据变了]
  → Vue 检测到变化，自动重新渲染列表                         [页面变了]
```

对着代码把这个链路亲手走三遍，比看十篇教程有用。

## 第三阶段：组件通信 + 综合实战（2 天）

- 读 `src/components/TodoItem.vue`：**props 向下传数据、emit 向上报告事件**，

- 读 `src/api/index.js`：为什么接口调用要单独抽一层（后端地址只写一次）

## 学会用两把调试利器

1. **console.log**：在任何函数里插一句 `console.log('拿到了:', todos.value)`，
   去浏览器 F12 的 Console 里看输出
2. **Vue DevTools**：Chrome/Edge 商店装这个官方插件，F12 里会多一个 Vue 标签，
   能直接看到每个组件的响应式数据实时值——比 log 更直观

## 常见新坑预警（都是高频问题）

- 改了 `ref` 忘写 `.value` → 页面不更新，控制台还可能报 undefined
- `v-for` 不写 `:key` 或用数组下标当 key → 列表更新时诡异错乱
- 在子组件里直接改 props → 数据流混乱（要用 emit 让父组件改）
- axios 返回的数据在 `.data` 里：`const res = await fetchTodos(); res.data` 才是后端内容
- 直接修改 reactive 数组的普通对象（本项目打字机 bug 的根源！）→ 界面不刷新，
  要用 `reactive()` 包过、或通过响应式引用去改
